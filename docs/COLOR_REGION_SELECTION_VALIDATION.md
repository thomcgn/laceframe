# Color-based region assignment and regional palette transfer

Date: 2026-11-18. Based on `origin/main` `9bb8326` (merged LF-03A / PR #29). Branch `feat/color-based-region-selection`, existing repository, no worktree. Initial working tree was clean and there were no open PRs. `.vscode/settings.json` was absent and remains untouched. Tests use synthetic temporary projects only; no private projects or live generation.

## Implemented workflow

**Farbkonsistenz prüfen → Haare / Bart, Haut, Kleidung or custom region → Auswahl nach Farbe** opens the color-first region editor. Original-image clicks, keyboard pixel coordinates and clickable dominant swatches pick actual visible RGB values. Explicit **Zur Region hinzufügen** / **Von Region entfernen** actions append ordered steps with individual Lab76 tolerance, global/four-neighbour connectivity and original seed coordinates/color. Global is the default; connected swatches start at their first actual occurrence, and the displayed seed coordinates make that choice explicit. Picking a different occurrence directly in the image changes the connected start point. Tolerance/mode changes affect the next explicit action, not previous saved steps.

The original image remains visible beneath a Sage selection overlay. Current selected palette swatches, color-group counts and the actual selected visible-pixel count/canvas coverage are shown. Coverage is a mask measurement, not an identity/style score. The palette is a bounded 5-bit RGB histogram with up to 16 actual representative colors, rather than an exhaustive inventory of every RGB value. Colors can be picked directly even when absent from these dominant swatches.

The existing MaskEditor remains available through **Pinsel für Feinkorrekturen**, with its zoom/pan, brush, eraser and own stroke history. Applying brush changes enters the same outer region history as color steps; undo/redo can cross picker and brush commits. A later color action takes precedence over earlier brush overrides within its selected pixels. The history uses the existing bounded-snapshot approach, capped at approximately 32 MiB for three mask planes (minimum one prior state, maximum 32). Color actions/replay run in a dedicated worker; closing cancels outstanding work. No intermediate image files or project writes are made. Masters and candidates use the same selection UI; candidate masks are still assigned explicitly, never inferred from equal dimensions or a similar pose.

**Region speichern** returns the draft mask; **Masterpalette als neue Revision speichern** persists an immutable palette revision. Existing brush-only revisions remain valid. New master-region metadata includes algorithm `color-region-lab76-v1`, ordered seeds/colors/tolerances/modes/actions, an immutable base mask, a binary manual-override mask and exact override values. Three content-addressed, read-only PNG mask references preserve legacy/soft brush weights without embedding multi-megabyte arrays in JSON. All use the existing color-mask path/hash/native-dimension/symlink boundary. Main recomputes the recipe and rejects mismatch with submitted weights before saving. Open and palette reads recheck the recipe against the exact original master. New revisions never mutate old masks/palettes.

Before the first selection or multi-group correction is written, `laceframe.v2.pre-color-selection.backup.json` retains the exact prior manifest (exclusive, conflicts rejected). Earlier migration backups remain in use. Older projects open without a write. Older strict-schema app versions cannot read the new optional fields; revert using the prior manifest and retained asset tree. Candidate selection steps are editing aids; saved correction provenance retains the exact candidate mask and correction parameters, while replayable color-selection recipes are stored with master regions.

## Transfer without full quantization

The selected region shows **Masterpalette**, original **Kandidatenpalette**, measured drift and **Masterpalette gezielt übertragen**. The explicit transfer proposes up to 16 source-to-reference color-group offsets using actual regional swatches. Near-identical candidate chroma shares one anchor (a/b distance <3); target choice minimizes a/b distance plus 0.25 × absolute L* difference, with deterministic histogram order for ties. The chosen pairs are displayed. These are numerical proposals, not recognition of hair/skin/clothes or a guarantee of semantic correspondence.

The existing correction engine applies a constant Lab offset to pixels belonging to a source chroma group, within the explicitly mapped candidate mask and configured group radius only. It preserves per-pixel shade/chroma differences instead of replacing pixels with palette entries. L* remains unchanged by default, allowing new dark anger/fear/sadness shadows. The existing explicit lightness checkbox permits a constant L* shift for genuinely lightened hair; strength remains adjustable. Selecting an individual source/target swatch returns to the existing selective single-group mode. Protected pixels, alpha and outside-mask pixels remain exact. Existing hard expression locks continue to be independently enforced in Main.

Save creates a separate candidate with exact source/master/palette binding, stored group parameters and CPU-verified preview pixel SHA-256. Human review/approval, historical expressions and exact stored PNG export remain unchanged. There are no new preload methods, file-system privileges, dependencies or image-generation calls.

## Limits

- Manual region assignment, no AI/semantic segmentation. Connected mode is four-neighbour connectivity, visible pixels require alpha ≥128. Fully transparent pixels never connect color selections; original RGBA is untouched.
- Maximum 4,194,304 pixels, five regions, 32 ordered color steps per region and 16 dominant swatches. No image downscaling. Palette transfer may miss rare colors outside the histogram and the group radius. Assign/review each candidate's region independently, especially for changed poses/dimensions.
- Nearest color groups are only a starting point. Different material colors can be close in Lab; clipping, byte rounding and group boundaries may reduce detail. Explicit lightness correction can clip very dark shadows. Inspect the result before approval; adjust strength/radius or use individual swatch pairs and protected regions.
- Only Linux validated. No new live image generation, automatic palette replacement, automatic identity approval or cross-platform packaging claim.
